Render the OMO sidebar on the OpenCode V2 TUI

On OpenCode V2 the right-hand pane only ever showed the host's own session
title, context and MCP list. The sidebar existed and was tested, but the V2 TUI
entry only raised a startup toast and never claimed a slot, so nothing was drawn.

- Claim `sidebar.content` from the V2 TUI plugin and render through the pipeline
  the V1 sidebar already uses (`readMirror` -> `computeView` -> `buildViewNodes`
  -> `materialize`). `tui.sidebar.enabled: false` still turns it off.
- Re-claim when the view actually changes. V2 calls a slot's `render` once and
  keeps the returned tree, so pushing new state through the same claim does not
  repaint; re-claiming goes through the registry's own subscription.
- Adapt the V2 theme before rendering. V2 resolves the theme into a nested RGBA
  tree (`text.base`, `text.feedback.error.base`, `border.base`), while the
  renderer was written against V1's flat string tokens. Passing an RGBA object
  as a `fg` prop made the host's colour clone throw, which the slot's error
  boundary swallowed, so the sidebar silently drew nothing.
- Bump `@opentui/solid`, `@opentui/core` and `@opentui/keymap` to `^0.8.4`, the
  versions `@opencode/plugin@2.3.2` declares as peers and the versions the V2
  host ships.
- Extract `materialize` and the view reader out of `src/tui.ts` so both the V1
  and V2 entries share one implementation. No change for V1.
