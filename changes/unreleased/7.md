### Fixed

- OMO agents show their display names on OpenCode V2. The bridge computed each agent's display name and then discarded it behind a `if (!agent.name)` guard, but V2 pre-fills `name` with the agent id, so the guard was always false and the picker rendered raw lowercase ids for OMO agents while the host's own agents rendered capitalized. An explicit config `name` still takes precedence, and an agent whose key has no display-name entry keeps the name V2 gave it.
- OMO's core agents are ordered `sisyphus -> hephaestus -> prometheus -> atlas` on OpenCode V2. The ported reorder helper could not work there: V2's agent schema has no `order` field, so the injected field was stripped, and V2 does not sort the agent list at all - it renders `Map` insertion order with the active agent hoisted to the front. Agents are now registered in canonical order, which is the only ordering lever V2 exposes, with `agent_order` overrides honored.
- A command's `agent` field is normalized to a config key before switching the session agent on OpenCode V2, so a display name in a V1 command config no longer fails to resolve against an id-keyed agent list.
