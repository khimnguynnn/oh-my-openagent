### Fixed

- `disabled_mcps` now takes effect on OpenCode V2. OMO resolves MCP servers in one place, `applyMcpConfig`, which merges the built-in servers, Claude Code `.mcp.json`, the user's own config and plugin components, then applies `disabled_mcps` and the user's `enabled: false` markers. On V2 the bridge ignored that answer and resolved MCPs again itself, calling `createBuiltinMcps` with a disabled list the runner never passed, so the setting was silently dead.
- `websearch.provider` is honoured on OpenCode V2 again. The same re-resolution passed `undefined` where the plugin config belongs, so `provider: "tavily"` was ignored and the Exa endpoint always won.
- MCP servers contributed by plugin components now reach OpenCode V2. The bridge merged only two of the four tiers.
- A server the user turned off with `enabled: false` is no longer registered on OpenCode V2.
