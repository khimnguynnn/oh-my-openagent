### Fixed

- OMO agent tool permissions take effect on OpenCode V2. Phase 4 of the config pipeline computed every grant and denial, but the bridge copied only the agent's name, model, system prompt, mode and description out of the V1 config, so every agent ran on V2's default ruleset: Librarian lost its `grep_app_*` grant, Atlas, Sisyphus and Prometheus lost `task`, `task_*` and `teammate`, Hephaestus lost `task`, and the global denials for `grep_app_*`, `task_*`, `teammate` and the LSP tools were never applied. V1's name-to-effect maps are now translated into the ordered `{ action, resource, effect }` rules V2 resolves with last-match-wins, with the per-agent overrides emitted last so an agent's grant still beats a global denial.
- `bash` and `task` permissions match on OpenCode V2. V2 checks the actions `shell` and `subagent`, and it only renames `bash`/`task` when it builds rules from its own config, so a rule handed to it through an agent's permission list is used verbatim and a `bash: deny` would never match. The bridge emits both the V1 name and the V2 alias whenever they differ.
