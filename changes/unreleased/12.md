Rich agent rows on the OpenCode V2 sidebar, and a config to turn the HUD off

The V2 sidebar drew one flat `name status` line per agent, and on V2 that line
was always absent: the plugin side builds `activeAgents` from
`client.session.status()`, which the V2 bridge returns as `{}` because V2 has no
status API. Every snapshot this project wrote carried `activeAgents: []`, so the
Agents section could not appear no matter what was running.

The TUI context carries the data instead (`ctx.data.session` plus
`ctx.data.location.agent`), which is where the sidebar now reads it. The mirror
still supplies the job board and the ULW loop, which both work on V2.

- Render each agent as a braille spinner (`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`), its model with
  variant, and its session title, with a status glyph for agents that are not
  running (`•` never ran, `✦` ran before, `⚰` finished). Colour follows the
  agent's own `color` when it names a theme token, `error`/`warning` when the
  status says so.
- Animate in place instead of re-claiming. Only `render` is destructive to
  repaint, so a spinner frame rewrites the mounted text node through
  `materializeTree`'s ref map and asks the renderer to repaint. The animation
  timer only runs while at least one agent is active, and `activeSince` is
  deliberately reduced to a presence flag in `viewKey`, so frames never re-claim
  the slot.
- Click a row to open its session through `ctx.ui.router`. The rows are scoped
  to the session the slot is painting, so the sidebar lists that session's
  family rather than every session in the project.
- Let live agent rows make the view active. `computeView` picks the idle roster
  whenever the mirror has no loop and no jobs, which is the normal state of a
  fresh V2 session, so folding the context rows in only after the view was
  already active meant a session with running subagents still showed nothing.
- Accept `tui.sidebar.enabled` as a top-level `omo.json` key. It was already
  honoured by the plugin schema and by `[opencode].tui`, but
  `omo-config-core`'s strict layer schemas did not know the key, so
  `{"tui":{"sidebar":{"enabled":false}}}` was reported as an unknown key. That
  diagnostic counts as a failure, which made the sidebar render
  `config invalid - run doctor` instead of hiding.
